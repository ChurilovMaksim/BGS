Все процессные следы агентной работы (формулы self-review, лексика subagent/сессий/скиллов, сессионные имена, пути среды в сохраняемых поверхностях, машинный кластер chat-research) из активного слоя убираются: публикуемые поверхности — точечная чистка; служебные пакеты — в архив целиком; честный слой — нейтральные академические переформулировки. Факты о методе верификации, на которых стоят статусы claims (чем проверено; проводилась ли независимая рецензия), не удаляются и не улучшаются задним числом — перефразируются без агентной лексики. В рукопись (рабочий свод) и в README вносится небольшая сноска: для работы с репозиторием, проверок и реализации кода использовались GPT 6 и Muse Spark 1.3.

## R2 — место архива (решено 22.10.2026)

Архив живёт внутри репозитория: `archive/` с манифестами «старый путь → blob SHA → коммит-источник». Отдельный репозиторий не создаётся.

## R3 — лицензия (решено 22.10.2026)

Послойно: код — MIT, тексты и данные — CC BY 4.0. Применяется при первом релизе (фаза 5); до релиза файл лицензии не вносится.

## R5 — механика массовых операций (решено 22.10.2026)

Массовые операции готовятся на локальном рабочем столе (снимок main); редактируется сам оригинальный `main` репозитория — каждый пакет уходит в него коммитом. Уточнение владельца: «мне нужно чтобы был отредактирован весь оригинальный main». SSH-транспорт из исполнительной среды закрыт сетевым прокси; снимок получен ZIP-архивом через веб-интерфейс GitHub и привязан к коммиту хэшем реестра claims.

В манифесте GitHub App «Meta Muse AI» разрешения Workflows нет (только metadata — чтение; code/issues/pull requests — чтение и запись), выдать его со стороны пользователя невозможно. Рабочий маршрут: файлы `.github/workflows/` вносятся через веб-сессию владельца, на которую ограничение манифеста не распространяется.

## CI: фикс пинов и блокировка биллинга (22.10.2026)

Коммит 81f181b: пины actions/checkout@v7→@v5 (×9) и actions/setup-python@v7→@v5 (×7) во всех четырёх workflow; upload-artifact@v4 не тронут. Проверка в Actions показала: задания не стартуют из-за блокировки биллинга аккаунта («recent account payments have failed or your spending limit needs to be increased») — та же аннотация стоит и на запусках до фикса; @v7 был латентным дефектом, а не причиной наблюдавшихся падений. На аккаунте исчерпаны минуты Actions за месяц; ведётся список долга CI, прогон — после сброса лимита, проверки тем временем выполняются локально.
