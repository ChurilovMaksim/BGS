# LLM Benchmark Comparison: Evidence Note

Date: 2026-09-01
Chat language: Russian
Work-product language: English
Scope: objective comparison of two LLMs, with emphasis on contamination, decoding, tools, reasoning modes, cost/latency, score comparability, and authoritative benchmark sources.

## Primary vendor sources

1. DeepSeek-R1 official repository and evaluation table
   - URL: https://github.com/deepseek-ai/DeepSeek-R1
   - Evidence: max generation length 32,768 tokens; for sampling benchmarks, temperature 0.6, top-p 0.95, 64 responses/query to estimate pass@1; multiple tests and averaging recommended. Usage guidance says temperature 0.5-0.7 (0.6 recommended), no system prompt, and a math prompt asking for step-by-step reasoning and a boxed final answer. It also recommends forcing an initial `<think>` for models that otherwise bypass the thinking pattern. The published table includes MMLU, MMLU-Redux, MMLU-Pro, DROP, IFEval, GPQA-Diamond, SimpleQA, LiveCodeBench, Codeforces, SWE Verified, AIME 2024, MATH-500, CNMO 2024, CLUEWSC, C-Eval and C-SimpleQA. The repository states that the distilled models were fine-tuned using samples generated by DeepSeek-R1.
   - Caveat: this is vendor-reported methodology and scores. The repository does not by itself establish absence of training/test contamination or independent reproduction of every score.

2. DeepSeek-R1 technical report
   - URL: https://arxiv.org/abs/2501.12948
   - Evidence: primary technical report for the R1 release; describes reasoning-oriented training and reported evaluations.
   - Caveat: use the repository's exact evaluation settings when reproducing the release table; do not infer comparability solely from the table's model names.

3. DeepSeek reasoning-mode documentation
   - URL: https://api-docs.deepseek.com/guides/thinking_mode
   - Use: authoritative API behavior and control surface for thinking/non-thinking modes; record the mode in every run.

4. DeepSeek tool-call documentation
   - URL: https://api-docs.deepseek.com/guides/tool_calls
   - Use: authoritative API contract for tool invocation; tool-enabled and tool-disabled scores are different system evaluations.

5. DeepSeek pricing
   - URL: https://api-docs.deepseek.com/quick_start/pricing
   - Evidence: prices are per 1M tokens and billing is based on total input/output tokens; current model tables also distinguish cache hit/miss and output pricing.
   - Caveat: prices are time-varying; store the retrieval timestamp and price snapshot with each cost report.

6. OpenAI simple-evals
   - URL: https://github.com/openai/simple-evals
   - Evidence: lightweight reference implementation published to make reported accuracy numbers transparent. It explicitly warns that evals are prompt-sensitive; its reference setting emphasizes zero-shot chain-of-thought prompts. It documents model-specific details including that o-series models do not support a system prompt, that o3-mini reasoning level in the table is medium, and that the listed o3/o4-mini results use no tools. For newer models it uses MATH-500 (an IID split) rather than the original MATH. The repository announced in July 2025 that it would no longer be updated for new models/results, while retaining reference implementations for SimpleQA, BrowseComp and HealthBench.
   - Caveat: treat it as a transparent historical/reference harness, not as a current universal leaderboard.

7. OpenAI Evals framework
   - URL: https://github.com/openai/evals
   - Evidence: supports registry evals, private/custom evals, JSON data and YAML configuration, model-graded evals, and completion functions for prompt chains and tool-using agents. The run documentation records events in JSONL and supports eval-set progress/resume; it warns that parallelism trades time against cost/rate limits. The README explicitly warns that API runs incur cost and that evaluation design requires experimentation.

8. OpenAI Evals dashboard documentation
   - URL: https://platform.openai.com/docs/guides/evals
   - Use: current product documentation for OpenAI evals workflow; verify endpoint behavior and model-version controls at run time.

9. OpenAI reasoning documentation
   - URL: https://platform.openai.com/docs/guides/reasoning
   - Use: current documentation for reasoning effort/budget controls and supported parameters; record the exact reasoning setting rather than treating an o-series name as a single fixed capability.

10. OpenAI API pricing
    - URL: https://openai.com/api/pricing/
    - Use: official pricing source. Record model/version, input/output/cached-token rates, date, and any reasoning-token billing field exposed by the API.

## Contamination-resistant and benchmark-method sources

11. LiveBench paper
    - URL: https://arxiv.org/abs/2406.19314
    - Evidence: designed to limit contamination by frequent updates and questions based on recently released information; uses objective ground truth and automatic scoring rather than an LLM judge.

12. LiveBench implementation and release controls
    - URL: https://github.com/LiveBench/LiveBench
    - Evidence: release option is an explicit CLI parameter; the repository documents monthly/fresh question releases, objective scoring, and configurable temperature/max tokens. It states that an OpenAI-compatible endpoint can be evaluated and that model/provider configuration is stored separately.
    - Caveat: a fresh release reduces but cannot prove zero contamination; report release date and model knowledge cutoff.

13. LiveCodeBench paper
    - URL: https://arxiv.org/abs/2403.07974
    - Evidence: continuously collects competitive-programming problems from LeetCode, AtCoder and Codeforces, filters by release time, and evaluates beyond plain generation (self-repair, execution, test-output prediction).

14. Contamination measurement paper
    - URL: https://doi.org/10.18653/v1/2023.findings-emnlp.722
    - arXiv: https://arxiv.org/abs/2310.18018
    - Evidence: argues contamination should be measured per benchmark rather than assumed away; use as a methodological source for overlap testing and reporting.

15. MMLU-Pro paper
    - URL: https://arxiv.org/abs/2406.01574
    - Official code: https://github.com/TIGER-AI-Lab/MMLU-Pro
    - Evidence: harder reasoning-focused questions, ten answer choices, removal of trivial/noisy items, and lower prompt sensitivity than original MMLU in the authors' experiments.

16. EleutherAI lm-evaluation-harness
    - URL: https://github.com/EleutherAI/lm-evaluation-harness
    - Evidence: unified framework with 60+ standard academic benchmarks, public prompts for reproducibility/comparability, task integrity checks, sample logging, explicit output paths, and support for API/local backends. It warns that answer extraction for closed chat APIs should be inspected on sample outputs before trusting scores.

17. HELM repository and paper
    - Repository: https://github.com/stanford-crfm/helm
    - Paper: https://arxiv.org/abs/2211.09110
    - Use: holistic evaluation reference covering multiple scenarios and metrics; use its scenario/metric separation as a model for reporting, but pin exact benchmark and version.

## Evidence boundaries

- Vendor README/system-card values are vendor-reported claims, not independent verification.
- Aggregators and leaderboards are discovery surfaces; canonical benchmark paper/repository and the benchmark owner's scoring code are authoritative for task definition and metric semantics.
- A score is not comparable unless benchmark release, prompt, shots, answer parser, decoding, reasoning budget, tools, retrieval, model endpoint/version and evaluation date are aligned.
