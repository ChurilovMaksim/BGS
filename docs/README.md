# Documentation map

The documentation tree intentionally keeps both current planning and the full research record.

## Current planning / status

- `programme_status.md` — current programme-level status, subordinate to root `STATUS.md`.
- `research_goals.md` — current goals.
- `roadmap.md` — current roadmap.
- root `STATUS.md`, `THEORY.md`, `research/README.md`, `research/M1.md` — canonical present-tense proof boundary.

## Research corpus

- `literature/` — literature notes and source reconnaissance.
- `review/` — referee/red-team/model-review material and the repository surgery audit.
- `ideas.md` — accumulated research ideas.
- `cycle2_falsifier.md` — falsifier work retained as part of the solution history.
- `trace_fluctuation_lemma.md` — conjectural/draft trace-fluctuation reduction; its own status label must be respected.
- `sp4_project_scope.md` — rank-2/Sp4 scope notes.
- `REVIEW_FINDINGS.md` — later review findings; use this before the superseded `REVIEW_ERRORS.md`.
- `REVIEW_ERRORS.md` — historical review report containing findings later corrected/refined; preserved for provenance.

## Detailed historical record

- `THEORY_FULL_PRE_REBUILD.md` — the detailed pre-rebuild theory notebook. It contains many valuable derivations but also historical theorem labels superseded by the 2026-09-02 audit.
- `HISTORY_FULL_PRE_REBUILD.md` — the full old research ledger. It is preserved verbatim and contains the known legacy text-encoding damage; root `HISTORY.md` is the concise current chronology.
- `archive/` — old run handoffs, ledger entries and snapshots retained at their original research granularity.

When two documents disagree about whether something is proved, use root `STATUS.md`. Do not discard the older document: it may contain the derivation, counterexample, numerical design or literature trail needed for the next iteration.
