# GOVERNANCE.md — проект для репозитория (пакет фазы 0, вносится в docs/)

## Роли
- **Владелец** (ChurilovMaksim): научные решения, статусы claims, лицензия, релизы; единственный, кто может менять настройки аккаунта/репозитория и биллинг.
- **Исполнитель переработки**: структура, редактура, верификация, пакеты изменений с манифестами; не меняет математическое содержание и статусы без записи в журнале решений.

## Правила
1. Ни одного изменения научных поверхностей в main без записи в `docs/decisions/` (что, почему, основание, как проверено).
2. Каждый пакет изменений: манифест (состав, старые/новые пути, blob SHA, коммит-источник) + независимый второй проход по чек-листу ниже до пуша.
3. Ничего не уничтожается: удаляемое из активного слоя переезжает в `archive/` с манифестом.
4. Файл, на который ссылается живой claim (evidence/source) или хэш в receipt, не двигается без одновременного переноса ссылки в том же коммите.
5. Статусы claims меняются только по процедуре научной перепроверки (фаза 7): strengthen-first, понижение — после документированной неудачной попытки усиления.
6. Workflow-файлы (.github/workflows/) вносятся через веб-сессию владельца (у GitHub App нет разрешения workflows в манифесте).

## Чек-лист второго прохода (перед каждым пушем)
- [ ] Дифф пакета сверен с манифестом построчно; ничего лишнего.
- [ ] Все пути из claims.json, затронутые пакетом, разрешаются после переезда.
- [ ] Локальные проверки пройдены: сборка рукописи (pdflatex), аудит-скрипты реестра/структуры, Lean-сборка формализации (если затронута).
- [ ] Запись в журнале решений заведена; долг CI пополнен, если CI недоступна.
- [ ] После пуша: HEAD сверен, результат доложен владельцу сводкой.

## Долг CI
При недоступности GitHub Actions ведётся `CI_DEBT`-список (локально у исполнителя, в репозиторий — сводкой на релизе): каждый пакет считается непокрытым CI до первого успешного прогона на итоговом main.
