## 1. Вопрос и ответ в одном абзаце

Вопрос: могут ли оценки Вейля, суммы Клоостермана и
равнораспределение по единицам mod g' закрыть следовую формулу
замороженного отображения точнее, чем диагональное приближение?

Ответ: да — но не тем способом, каким это обычно представляют.
Точность даёт не глубокая оценка экспоненциальной суммы, а
точная арифметика конечной группы:

1. Окно `N ∈ (X, 2X]`, `gcd(N, D_m) = 1` — это почти полные блоки
   вычетов mod g'. В каждом полном блоке обратные вычеты
   `ν_N = N⁻¹ mod g'` пробегают каждую единицу ровно одинаковое
   число раз. Поэтому среднее по окну отличается от среднего по
   единицам только краевыми неполными блоками — ошибка `O(1/X)`,
   без всякого √.
2. Среднее по единицам самого профиля `Btup` вычисляется
   **точно** через суммы Рамануджана. Внедиагональные пары мод
   не «малы по Вейлю»: они равны `μ/φ` — а для
   делитель-резонансных пар равны ровно `±1`, то есть вовсе не малы.
   Их нельзя убить аналитикой; их надо классифицировать структурно.

То есть арифметика здесь не «оценка», а **точное тождество
плюс подсчёт блоков**. Диагональное приближение грубее: оно
отбрасывает все внедиагональные пары, а рамануджановская формула
их считает точно.

## 2. Объекты (фиксированное m, фиксированный кик η)

Из 163 (в кортежной переигровке моста):

- `Dm = D_m = 2(x_m − 1)`, `gp = g'_m`, `yp = y'_m`,
  причём `gp ∣ Dm` (доказано в мосте) и `gcd(yp, gp) = 1`
  (по построению: числитель и знаменатель поделены на общий
  делитель).
- Окно: `W_X = {N : X < N ≤ 2X, gcd(N, D_m) = 1}`.
- Для `N ∈ W_X` определён `ν_N ∈ (Z/gp)ˣ` условием
  `ν_N · N = 1` в `Z/gp` (возможно, так как `gp ∣ D_m`).
- Профиль: `Ztup(ν) = ∑'_{n} phiFun(n) · e(−ν·yp·NmZ(n)/gp)`,
  `Btup(ν) = ‖Ztup(ν)‖²`, где `e(t) = exp(2πi·t)`,
  `s0 = ∑_k ‖ĝ_k‖`, `s2 = ∑_k k²‖ĝ_k‖`.
  Из моста: `‖Ztup(ν)‖ ≤ s0^m`, откуда `Btup(ν) ≤ s0^{2m}`.
- Цель 175 (единичная версия): `hEquidistUnits` —
  ```
  | winAvg(W_X, Btup ∘ ν) − nuAvgUnits(Btup) |
      ≤ D · min(s0^{2m}, Deff) / X.
  ```
  Здесь `winAvg` — среднее по окну, `nuAvgUnits` — среднее
  по единицам mod gp. Параметры `D, Deff` в мосте свободны;
  в исходной границе 175 стоит `D_m · min(s0^{2m}, D_eff)/X`.

Заметьте, что в этой постановке уже исправлена главная ошибка
старого моста: таргет — среднее по **единицам**, а не по всем
вычетам. Среднее по всем вычетам недостижимо для `ν_N`:
`ν_N` никогда не бывает не-единицей, поэтому при m=1
соответствующая `hEquidist` доказательно ложна (контрпример
в `LineBNAverageM1`). Вся арифметика ниже — про единицы.

## 3. Что делает диагональное приближение — и чего оно не делает

В полуклассике «диагональ» — это пары одинаковых орбит
(здесь: пары мод `n = n'`). Для профиля:

```
Btup(ν) = ∑_{n,n'} phiFun(n)·conj(phiFun(n'))
            · e(−ν·yp·(NmZ(n) − NmZ(n'))/gp).
```

Диагональ `n = n'` даёт `∑_n |phiFun(n)|²` — не зависящий
от ν главный член. Диагональное приближение отбрасывает
остальное и надеется, что оно мало после усреднения.
Это неверно в двух смыслах:

- После усреднения по единицам внедиагональ **не стремится
  к нулю как ошибка**: она равна точной рамануджановской
  величине (§6), которая для резонансных пар равна `±1`.
- После усреднения по окну внедиагональ не нуждается в
  оценке типа `√gp`: полные блоки дают её **точно** (§4–§5).

Поэтому «точнее диагонали» здесь означает: не оценивать
внедиагональ сверху, а **вычислить её среднее точно**,
а остаток свести к подсчёту краёв окна.

## 4. Кандидат C-block: равнораспределение — это подсчёт блоков

### 4A. Безусловный вариант (блоки mod D_m, для всех m)

Пусть `L = D_m`. Интервал `(X, 2X]` разбивается на полные
блоки длины `L` и не более двух неполных краевых блоков.
Ключевой шаг — **равные слои** редукции:

> Отображение редукции `(Z/D_m)ˣ → (Z/gp)ˣ` сюръективно,
> и каждый слой имеет ровно `φ(D_m)/φ(gp)` элементов.

Это гомоморфизм конечных абелевых групп; сюръективность —
по китайской теореме об остатках по примарным компонентам
(для каждого простого `p`: условие mod `p^{v_p(gp)}` задано
единицей, а на остальных примарных компонентах можно взять 1).
Отсюда: в каждом полном блоке длины `D_m` значения `ν_N`
пробегают каждую единицу ровно `φ(D_m)/φ(gp)` раз, а значит
среднее `Btup(ν_N)` по полному блоку **равно в точности**
`nuAvgUnits(Btup)`.

Следствие (схема доказательства, не доказательство):
разность среднего по окну и среднего по единицам создаётся
только неполными блоками, которых не более `2·D_m` штук.
С грубой оценкой `|Btup| ≤ s0^{2m}` и нижней оценкой
`|W_X| ≥ φ(D_m)·X/(2·D_m)` при `X ≥ 4·D_m` это даёт
`O(D_m²/φ(D_m) · s0^{2m}/X)` — уже `O(1/X)`, без Вейля.
Константа плохая, но порядок правильный. Улучшение — в §5.

### 4B. Условный вариант (блоки mod gp, если верна лемма о радикале)

**Подлемма о радикале (КАНДИДАТ).** Простые делители `D_m`
и `gp` совпадают: `rad(D_m) = rad(gp)`.

Для нечётного простого `p ∣ D_m` это доказывается в одну
строку из тождества Пелля `x² − 8y² = 1`, то есть
`(x−1)(x+1) = 8y²`. Если `p ∣ x−1`, то `p ∤ x+1` (они
отличаются на 2), значит `v_p(x−1) = 2·v_p(y)`, откуда
`v_p(y) < v_p(x−1)` при `v_p(x−1) > 0`, то есть `p ∣ gp`.
Случай `p = 2` этим аргументом не закрывается и остаётся
отдельной подзадачей (проверен для m ≤ 10 по таблицам,
но общего доказательства здесь нет — см. §10).

Если лемма о радикале верна, то
`gcd(N, D_m) = 1 ⟺ gcd(N, gp) = 1`, и окно — это в точности
единицы mod gp, повторяющиеся по интервалу. Тогда полные
блоки — длины `gp`, а не `D_m`, и все константы резко
улучшаются (для m=5: `gp = 82` вместо `D_m = 6724`).
Численно это видно уже при `X = 1000 < D_5` (§9, тест T1):
счётчики по единицам mod 82 равны 12–13, хотя полных
блоков mod 6724 в окне нет вовсе. Это — экспериментальное
подтверждение варианта 4B, а не 4A.

**Важное разграничение.** Вариант 4B не нужен для порядка
`O(1/X)` (его даёт 4A), он нужен для хорошей константы
и для режима `gp ≪ X ≪ D_m`. Если лемма о радикале
окажется ложной при каком-то m, кандидат не умирает:
он отступает на 4A с худшей константой и режимом `X ≫ D_m`.

## 5. Кандидат C-sharp: константа `4·gp`, а не `D_m`

Грубая оценка §4A теряет порядок, потому что оценивает
каждый краевой член максимумом `s0^{2m}`. Более острый
подсчёт использует отклонение счётчиков:

- Пусть `c_ν` — число `N ∈ W_X` с `ν_N = ν`. Для варианта 4B
  числа `c_ν` (по единицам) отличаются друг от друга не
  более чем на 1: интервал даёт каждый вычет mod gp либо
  `k`, либо `k+1` раз. Значит `|c_ν − |W_X|/φ(gp)| ≤ 1`.
- Тогда, полагая `δ_ν = c_ν/|W_X| − 1/φ(gp)`,
  `|winAvg − nuAvgUnits| = |∑_ν δ_ν·Btup(ν)|`
  `≤ (1/|W_X|) · ∑_ν Btup(ν)`.
- Сумма по единицам: `∑_ν Btup(ν) ≤ φ(gp)·s0^{2m}`
  (каждое слагаемое `≤ s0^{2m}`).
- При `X ≥ 4·gp` имеется `|W_X| ≥ (φ(gp)/gp)·X/2`
  (с запасом; точная нижняя оценка — лемма для Lean).

Собирая с запасом 4 на краевые эффекты, получаем
**целевую форму кандидата**:

```
| winAvg(W_X, Btup ∘ ν) − nuAvgUnits(Btup) |
    ≤ (4·gp / X) · s0^{2m}          (при фиксированном m, X ≥ 4·gp)
```

Сравнение с исходной константой `D_m`: для m=3
`4·gp = 56 < D_3 = 196`; для m=5 `4·gp = 328 < D_5 = 6724`.
То есть кандидат даёт **ветвь `s0^{2m}`** исходной границы
с константой лучше, чем `D_m`.

**Честная оговорка про `min`.** Ветвь `Deff` (то есть
`D_m·Deff/X` при `Deff < s0^{2m}`) этим подсчётом **не
закрывается**: она потребовала бы оценки
`∑_ν Btup(ν) ≤ (что-то)·Deff`, которой у нас нет
(`Btup(ν)` не имеет малого носителя по ν; `Deff` в Derand —
это `D_m/radSize`, геометрическая величина, а не носитель
профиля). Для затухания это не критично: при логарифмическом
окне `s0^{2m} ≤ X^{1−ε}`, и ветви `s0^{2m}` хватает, чтобы
ошибка убывала как `X^{−ε}` с точностью до множителя `gp`.
Но verbatim-константа `D_m·min(…)/X` остаётся отдельным,
меньшим пробелом — и его нельзя замазывать, называя
кандидат полным доказательством 175.

## 6. Кандидат C-Ramanujan: точное среднее по единицам

Усреднение по единицам вычисляется точно. Для
`a ∈ ℤ` пусть `c_q(a) = ∑_{u∈(Z/q)ˣ} e(a·u/q)` —
сумма Рамануджана. Классическая формула:
если `d = gcd(a, q)`, то
`c_q(a) = μ(q/d)·φ(q)/φ(q/d)`, где `μ` — функция Мёбиуса.
Отсюда для среднего профиля:

```
nuAvgUnits(Btup) =
  (1/φ(gp)) · ∑_{n,n'} phiFun(n)·conj(phiFun(n'))
      · c_{gp}(−yp·(NmZ(n) − NmZ(n'))).
```

Так как `gcd(yp, gp) = 1`, множитель `yp` на `gcd` не влияет:
важен только `d = gcd(NmZ(n) − NmZ(n'), gp)`, и вклад пары
равен `μ(gp/d)/φ(gp/d)`:

| `d = gcd(Δ, gp)` | вклад пары в среднее |
|---|---|
| `d = gp` (в частности диагональ `Δ = 0`) | `+1` |
| `gp/d` — простое `p` | `−1/φ(p) = −1/(p−1)` |
| `gp/d` — произведение двух простых | `+1/φ(gp/d)` |
| `gp/d` не свободно от квадратов | `0` |
| `d` таков, что `gp/d` — простое, но `φ = 1` | `−1` — **резонанс** |

Последняя строка — главное. Если `gp/d = 2`, то есть
`Δ` делится ровно на `gp/2`, вклад равен `−1`: пара
вносит столько же, сколько диагональ, с обратным знаком,
**для всех ν одновременно**. Проверить на примерах:

- **m = 3:** `gp = 14`, `yp = 5`. Пары с `Δ`, делящимся
  на 7, но не на 2 (`d = 7`), дают `−1`. Действительно,
  фаза `e(−ν·5·7/14) = e(−5ν/2) = −1` для всех нечётных ν
  (а единицы mod 14 — ровно нечётные, не делящиеся на 7).
  Пары с `gcd(Δ,14) = 1` дают `+1/6`, с `gcd = 2` — `−1/6`.
- **m = 5:** `gp = 82`, `yp = 29`. Пары с `Δ`, делящимся
  на 41, но не на 2 (`d = 41`), дают `−1`. Пары с
  `gcd(Δ,82) = 1` дают `+1/40`, с `gcd = 2` — `−1/40`.

**Вывод для метода.** Резонансные пары (`gp/d` простое
с `φ = 1`, то есть `gp/d = 2`) — это не «ошибка», которую
можно оценить сверху: это структурный вклад, равный по
величине диагонали. Его судьба решается не суммой
Клоостермана, а вопросом: **какие разности `NmZ(n) − NmZ(n')`
вообще встречаются, и с какими весами?** Это территория
hSep, Γ-орбит и носителя мод — то есть структурной
теории, а не аналитической оценки. Любой «метод»,
обещающий убить резонанс оценкой `O(√gp)`, ложен:
резонанс точен и равен `−1`.

## 7. Где Вейль и Клоостерман действительно нужны (и где нет)

Стандартная оценка Вейля для сумм Клоостермана
(при простое `p`, `(a,b) ≠ (0,0) mod p`):
`|∑_{u∈F_pˣ} e((a·u + b·u⁻¹)/p)| ≤ 2√p`,
для составного модуля — с множителем числа делителей.
Это глубокая теорема (Вейль 1948; в полной общности —
Делинь), и в Mathlib её нет: формализация пути через
Вейля была бы отдельным огромным проектом. Тем важнее
точно знать, где без неё нельзя, а где она — лишний вес.

**НЕ нужна — hEquidistUnits при фиксированном m, X → ∞.**
Полные блоки дают точное равенство (§4), а не оценку.
Применение Вейля здесь дало бы худший результат
(`√gp` вместо точного нуля на полных блоках).

**Нужна, возможно, в трёх местах:**

1. **Короткие окна и равномерность по m.** Если окно
   короче `gp` (или `m` растёт с `X`, так что `gp`
   сравнимо с `X`), полных блоков нет, и остаток — это
   неполная сумма вида `∑_{N∈окно} e(a·N⁻¹/gp)`.
   Её нетривиальная оценка — это неполная сумма
   Клоостермана: доработка полной суммы (Вейль) даёт
   выигрыш только при длине окна `≫ √gp·log gp`.
   При `X ≲ √gp` даже Вейль не даёт убывания — это
   жёсткий порог метода, а не техническая деталь.
2. **Совместное усреднение с фазой `Q/N`.** Следовая
   формула содержит, кроме `ν`-фазы, множитель
   `e(Q(n)/N)`, зависящий от `N` не только через `ν_N`.
   Поточечная оценка моста уже сводит его к `O(1/N)`,
   но если захотеть точную константу `2π` (а не `≈2π`),
   понадобится совместное усреднение пары
   `(N⁻¹ mod gp, Q/N mod 1)` — а это уже сумма с
   аддитивной и мультипликативной фазами одновременно,
   где Клоостерман — естественный язык.
3. **Высшие моменты и форм-фактор.** `hEquidistUnits`
   закрывает только первый момент `|Tr|²` (среднее).
   Микроскопическая статистика BGS требует всех
   корреляций, а там появляются суммы по нескольким
   обратным вычетам — многомерные аналоги Клоостермана,
   для которых нет готового «точного» трюка с блоками.

Ни один из этих трёх пунктов не является шагом,
нужным для 175 при фиксированном m. Поэтому ответ
на вопрос задания: **Вейль не закрывает 175 точнее
диагонали; блоки и Рамануджан закрывают точнее — но
только среднее, а не всю BGS.**

## 8. Связь с фазовой заменой t* (общий корень двух ложных утверждений)

Фазовая замена (PhaseLemma) и кандидат здесь — один
и тот же принцип в двух обличьях:

- Ложный коллапс 150 утверждал: `t*(N)` зависит только
  от `N mod gp` (как число). Ложно: при m=3
  `t*(1) = −1/196`, `t*(15) = 13/196`, разность `−1/14 ∉ ℤ`.
  Истина: `t* = k/D_m`, и `N·k ≡ −1 (mod e)` для `e ∣ D_m`;
  то есть от вычета зависит `k mod gp`, а значит —
  **фазы**, а не само `t*`.
- Ложная `hEquidist` утверждала: среднее по окну равно
  среднему по **всем** вычетам. Ложно при m=1.
  Истина: `ν_N` принимает только значения-единицы,
  и среднее по окну равно среднему по **единицам** —
  опять с точностью до краёв блоков.

Общий корень ошибки в обоих случаях: забыть, что
релевантное множество — это **единицы**, а релевантный
объект — **фаза**, а не параметр. Кандидат M03 — это
просто проведение этого принципа до конца: всё, что
зависит от `N`, зависит от него только через `ν_N`,
а всё, что зависит от `ν`, усредняется точно.

## 9. Простейшие случаи и тесты, которые убьют подход

### Числа для m = 3 и m = 5 (проверены прямым счётом)

| | m = 3 | m = 5 |
|---|---|---|
| `x_m, y_m` | 99, 35 | 3363, 1189 |
| `D_m` | 196 = 2²·7² | 6724 = 2²·41² |
| `gp` | 14 = 2·7 | 82 = 2·41 |
| `yp` | 5 | 29 |
| `φ(gp)` | 6 | 40 |
| Единицы mod gp | 1, 3, 5, 9, 11, 13 | нечётные < 82, кроме 41 |
| Обратные | 1↔1, 3↔5, 9↔11, 13↔13 | см. скрипт ниже |

**Тест T1 (блоки, уже пройден).** Окно `X = 1000`:
m=3: `|W| = 428`, счётчики по единицам — 71 или 72
(среднее 71.33); m=5: `|W| = 488`, счётчики — 12 или 13
(среднее 12.2). Отклонение счётчика от среднего ≤ 1 —
ровно то, что предсказывает §5. Если бы при каком-то
`X` счётчик отклонился больше чем на 1 (для варианта 4B)
или если бы среднее по окну для ступенчатой функции
`B = 1_{ν=ν₀}` отклонилось от `1/φ` больше чем на
`1/|W|`, вариант 4B мёртв.

**Тест T2 (Рамануджан, уже пройден для чистой арифметики).**
Прямой подсчёт `∑_{u∈units} e(−a·u/q)/φ(q)` совпал
с формулой `μ(q/d)/φ(q/d)` для всех проверенных `a`:
m=3: `a=1 → +1/6`, `a=2 → −1/6`, `a=7 → −1`;
m=5: `a=1 → +1/40`, `a=2 → −1/40`, `a=41 → −1`.
Следующий шаг — тот же тест на синтетическом профиле:
взять любые веса `w_n` и целые `Nm_n`, положить
`Z(ν) = ∑_n w_n·e(−ν·yp·Nm_n/gp)`, вычислить среднее
`Btup` по единицам brute force и сравнить с суммой
по парам с рамануджановскими весами §6. Несовпадение
убьёт либо формулу фазы, либо отождествление `yp`.

**Тест T3 (резонанс, убивающий «оценочный» подход).**
Синтетический профиль из двух мод с `Nm`-разностью
`Δ = 7` при m=3: вклад пары должен быть **постоянным
−2·Re(w₁·conj(w₂)) при всех ν** (фаза `−1`).
Если brute force даст ν-зависимость — неверна сама
фаза `phaseTup`. Если даст постоянство — доказано
на примере, что резонанс нельзя «оценить», его надо
считать: любая будущая оценка внедиагонали, дающая
`< 1` для такой пары, ложна.

**Тест T4 (короткое окно — граница метода).**
Взять `X = 10` при m=3 (`gp = 14`): окно `(10, 20]`
содержит меньше одного полного блока mod 14.
Расхождение среднего по окну и среднего по единицам
для ступенчатой `B` должно быть порядка `O(1)`,
а не `O(1/X)` с малой константой. Если бы оно
оказалось малым для всех `B` — это означало бы
дополнительную структуру, которой у нас нет, и
потребовало бы пересмотра всей картины. Ожидаемый
исход — большое расхождение: метод блоков честно
заявляет свой режим `X ≫ gp`.

**Тест T5 (порог Вейля для неполных сумм).**
Для `S(L) = ∑_{N≤L, (N,gp)=1} e(N⁻¹/gp)` (m=5, `gp=82`)
сравнить `|S(L)|` с тривиальной оценкой `L` и с
`√gp·log gp ≈ 40` при `L = 20, 50, 100, 200`.
Если `|S(L)|` остаётся порядка `L` при `L ≫ 40`,
доработка по Вейлю в этой форме не работает, и
короткое окно требует другого метода (например,
оценок Бёрджесса для мультипликативных характеров,
а не Клоостермана). Этот тест не убивает главный
кандидат (он живёт при `X ≫ gp`), но убивает
претензию «Вейль закроет и короткое окно».

Скрипт для T1/T2 (Python, только проверка арифметики,
не доказательство):

```python
import math, cmath
for m, gp, yp in [(3, 14, 5), (5, 82, 29)]:
    Dm = {3: 196, 5: 6724}[m]
    units = [u for u in range(gp) if math.gcd(u, gp) == 1]
    X = 1000
    W = [N for N in range(X + 1, 2 * X + 1) if math.gcd(N, Dm) == 1]
    from collections import Counter
    cnt = Counter(pow(N, -1, gp) for N in W)
    print(m, "|W| =", len(W), "counts:", sorted(set(cnt.values())),
          "missing:", [u for u in units if u not in cnt])
    for a in [1, 2, gp // 2]:
        s = sum(cmath.exp(-2j * math.pi * a * u / gp) for u in units) / len(units)
        print("  a =", a, "units-average =", round(s.real, 6))
```

## 10. Что этот кандидат НЕ закрывает

1. **Микроскопическую BGS.** Закрыт (в случае успеха)
   только первый момент `|Tr U_N^m|²` в среднем по окну.
   Статистика расстояний между уровнями, форм-фактор
   на времени Гейзенберга, все высшие корреляции —
   открыты и требуют других идей.
2. **Идентификацию `kickMatInf`.** Мост работает с
   формальным бесконечным киком; что это — настоящий
   квантовый кик замороженного отображения, — входная
   установка, а не следствие арифметики.
3. **Идентификацию `Psi_m = PsiMode`.** Фазовая замена
   живёт на уровне модовых сумм; что граничный `Psi_m`
   равен такой сумме — аналитический слой 149-full
   (`hTrace`, `hAvg`, `hPair`), открытый.
4. **Точную константу `D_m·min(…)`.** Закрыта ветвь
   `s0^{2m}` с константой `4·gp`; ветвь `Deff` — нет (§5).
5. **Случай `p = 2` в лемме о радикале** и равномерность
   по `m` (логарифмическое окно, где `gp` растёт с `X`).
6. **hSep, J0-ансамбль, симметрию коэффициентов `c`.**
   Резонансные пары §6 — это как раз то место, где
   эти открытые структуры должны войти: без них
   формула Рамануджана даёт среднее, но не объясняет,
   почему резонансные вклады не разрушают RMT-картину.

**Итоговая оценка метода.** Арифметика и экспоненциальные
суммы — правильный язык для 175, но правильная теорема
здесь — не Вейль, а **точное тождество Рамануджана
плюс подсчёт блоков**. Вейль — это запасной метод
для режимов, где блоки кончаются. Путать эти два
режима — значит либо требовать от Вейля невозможного
(убить резонанс `−1`), либо не замечать, что главный
шаг уже элементарен.
