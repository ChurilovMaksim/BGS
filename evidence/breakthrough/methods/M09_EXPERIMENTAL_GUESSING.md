локальные снимки источником истины не являются.

## 0. Идея метода в одном абзаце

Экспериментальная математика здесь — это не «подогнать кривую под
точки», а способ найти точную структуру там, где прямое доказательство
пока не видно: считаем малые случаи в точной арифметике, замечаем
закономерность, формулируем её в самом сильном виде, который ещё
может быть правдой, а затем пытаемся её убить. Если закономерность
выживает при смене параметров, чётности, носителя и при переходе
к бо́льшим значениям, она становится кандидатом на структурное
доказательство. Если умирает от одного контрпримера — это тоже
результат: ложная ветка закрыта дёшево, до дорогой работы в Lean.

Классический пример из самого проекта, почему это нужно: гипотеза
коллапса `t*` по вычетам выглядела правдоподобно, но один точный
контрпример при `m = 3` (`D = 196`, `g' = 14`, `t*(1) = −1/196`,
`t*(15) = 13/196`, разность `−1/14 ∉ ℤ`) убил её полностью. Правильная
замена — фазовая лемма `t* = k/D`, `N·k ≡ −1 (mod e)` при `e ∣ D` —
тоже сначала видна из таблицы, а потом доказывается структурно.

первым делом проверяется, тот ли объект считается, а не подгоняется

## 2. Протокол: семь шагов от таблицы к кандидату

### Шаг 1. Заморозить определения и записать их дословно

Перед первым вычислением — выписать определения из §1 и номера
файлов, откуда они взяты. Любое расхождение в определении (например,
линейное расстояние `|i−j|` вместо циклического, среднее по всем
вычетам вместо среднего по единицам) делает весь эксперимент
мусором. История проекта знает оба случая: среднее по всем вычетам
дало ложный таргет для 175, а линейное расстояние — это то, что
стоит в `NmZ` и `Xm`, и его нельзя молча заменить циклическим.

### Шаг 2. Точная арифметика сначала, float — только потом

Порядок инструментов по доверию:

1. Целые числа и дроби (`Fraction`): `D_m`, `g'`, `y'`, `k*`,
   подсчёты по окну, суммы Рамануджана. Здесь равенство — точное.
2. Алгебраические числа / циклотомические суммы: фазы — корни
   из единицы; суммы по единицам сводятся к суммам Рамануджана
   (см. кандидата C3), которые целочисленны. Если float-результат
   «почти целый» с ошибкой `10⁻⁹`, это ещё не целое число.
3. Float (`float`/`complex`) — только для разведки и для
   величин, где точная сумма недоступна (бесконечные `tsum` по
   модам при общем `ĝ`). Float-совпадение никогда не записывается
   как равенство; записывается как «совпало до `ε` на таком-то
   наборе», и следующий шаг обязан быть точным или структурным.

Метод Барейса для детерминанта, а не float-`det`, — обязателен:
float-детерминант при `D_m ~ 10⁹` уже не различает соседние целые
значения надёжно.

### Шаг 3. Разделить открытие и проверку (discovery / holdout)

- **Discovery-набор:** малые значения, на которых формула
  угадывается (например, `m = 1..7`).
- **Holdout-набор:** значения, которые при угадывании не
  использовались (например, `m = 8..12`, затем `m = 13..30`).
  Формула, подогнанная под discovery и провалившаяся на holdout,
  выбрасывается, а не «чинится» добавлением члена.
- Отдельный holdout по другому измерению: если формула угадана
  по `m`, проверяется по `N` (окно, `t*`); если по одному `ĝ`,
  проверяется по другому `ĝ` и по другому носителю.

### Шаг 4. Бюджет параметров

Правило, отличающее формулу от подгонки: число свободных
параметров формулы должно быть мало по сравнению с числом
независимых проверенных точек, и каждый параметр должен иметь
структурный смысл (чётность, делитель, характер, сумма Рамануджана),
а не быть «коэффициентом, подобранным по таблице».

- Подозрительно: формула с 3–4 свободными константами,
  «объясняющая» 5 точек.
- Убедительно: формула без свободных параметров (как C1 ниже:
  только чётность `m`), совпадающая на 30 значениях.
- PSLQ / целочисленные соотношения и поиск в OEIS — это
  подсказки, а не доказательства. Найденная в OEIS последовательность
  обязана пройти holdout и структурную проверку: совпадение первых
  10 членов ничего не доказывает (классический пример — многочлены,
  совпадающие на первых значениях и расходящиеся дальше).

### Шаг 5. Две независимые реализации

Каждую величину считают два разных кода (или код и ручная
пересборка из другого определения). Расхождение — стоп-сигнал,
а не повод усреднить.

Поучительный случай из этой же работы: при подсчёте суммы
Рамануджана первая версия функции Мёбиуса теряла чётность
числа простых делителей для остаточного простого множителя,
и разложение «диагональ + внедиагональ» дало неверный итог
(`−0.9375` вместо `6.5625` для игрушки `m = 3`). Ошибка поймана
только перекрёстной проверкой: прямым вычислением среднего
`B(ν)` по единицам. Правило отсюда: **ни одна формула не
принимается, пока её не воспроизвёл второй, независимо написанный
считатель**.

### Шаг 6. Граничные случаи — обязательный набор убийц

Каждая формула прогоняется через:

- `m = 1` и `m = 2` (вырожденные `H₁ = [4]`, `H₂ = [[6,−2],[−2,6]]`);
- чётные и нечётные `m` отдельно (в проекте чётность меняет
  формулы: квадрат против полуквадрата, см. C1);
- `N`, не взаимно простое с `D` (формула для `t*` там вообще
  не определена — попытка применить её должна явно падать,
  а не давать «почти верный» ответ);
- малые окна, где окно пусто или содержит одно `N`;
- `ĝ` с нулём, с асимметричным носителем, с комплексными
  значениями (вещественность может случайно держаться на
  симметричном примере и рушиться на общем);
- замену среднего по единицам на среднее по всем вычетам
  (контроль: если формула «работает» и там, она, скорее всего,
  тривиальна или неверно понята — для 175 это ровно та ошибка,
  которая уже стоила проекту ложного таргета).

### Шаг 7. Критерии продвижения кандидата

Кандидат допускается к попытке структурного доказательства, если:

1. он точен (или точно сформулирован как неравенство с явной
   константой) на discovery + holdout;
2. у него есть названный убийца — конкретный контрпример,
   который его опроверг бы (см. §4 для каждого кандидата);
3. есть хотя бы набросок структурного маршрута: какая лемма
   (тождество Пелля, сумма Рамануджана, подсчёт вычетов)
   могла бы его дать, а не только «похоже на правду»;
4. он не дублирует уже доказанное: сначала проверяется, нет ли
   этой же формулы в проекте в виде конечного `decide`-сертификата
   (как `D_closed` ниже) — тогда задача не «открыть», а
   «обобщить конечный сертификат на все `m`».

## 3. Как отличить истинную формулу от подгонки: контрольный список

| Признак | Подгонка | Кандидат на теорему |
|---|---|---|
| Параметры | Подобраны под точки, без смысла | Нет или только чётность/делитель |
| Holdout | Падает при `m+1` | Держится на `m` до 30 и дальше |
| Чётность | «Работает для нечётных» без объяснения | Чётность входит в формулировку и в маршрут доказательства |
| Смена `ĝ` | Ломается | Держится для двух-трёх разных `ĝ` |
| Смена объекта | Работает только для одной величины | Та же структура видна в соседней величине (например, `g'` и `y'` одновременно) |
| Точность | Float `≈` с `ε ~ 10⁻³` | Точное целое равенство или float `≤ 10⁻¹²` с точным маршрутом |
| Убийца | «Трудно придумать» | Назван явно, и тест на него уже запущен |

Особо опасные ловушки:

- **Float-целые.** Сумма фаз почти всегда «почти целая» при
  малом `g'` из симметрий; это не доказательство целочисленности.
- **Малые `g'`.** При `g' = 2` среднее по единицам — это одно
  значение `B(1)`; любая формула, «проверенная» только при `m = 1`,
  ничего не проверяет.
- **Диагональное приближение.** Среднее по единицам **не** равно
  диагональному вкладу (см. C3: для игрушки `m = 3` диагональ
  `12.875` против истинного среднего `6.5625`). Формула, отбрасывающая
  внедиагональ, убивается этим примером мгновенно.
- **Полные блоки.** Аргумент «в полном блоке длины `D` всё
  равномерно» даёт ошибку порядка `D/X`, но не точную константу
  и не объясняет, почему на практике разброс на порядок меньше
  (см. C2).

## 4. Три кандидата, полученные этим протоколом

### C1. Квадратная формула для `g'` и `D_m` — КАНДИДАТ (обобщение конечного сертификата)

**Формулировка.** Пусть `(1 + √2)^m = u_m + v_m√2` (целые `u_m, v_m`,
`u_m² − 2v_m² = (−1)^m`). Тогда для всех `m ≥ 1`:

- `m` нечётно: `g'_m = 2u_m`, `y'_m = v_m`, `D_m = (g'_m)²`;
- `m` чётно: `g'_m = 4v_m`, `y'_m = u_m`, `D_m = (g'_m)²/2`.

Эквивалентно: `x_m − 1 = 2d_m²` при нечётном `m` и `x_m − 1 = 4d_m²`
при чётном `m`, где `d_m = u_m` (нечётный случай) или `d_m = v_m`
(чётный случай).

**Что проверено.** Точная целочисленная проверка: таблица §1
совпадает с формулой для `m = 1..20` (по `u_m, v_m`), а равенства
`D_m = (g'_m)²` (нечётные) и `D_m = (g'_m)²/2` (чётные) — для
`m = 1..30` (Pell-рост не мешает: числа при `m = 30` порядка
`10²³`, Python-целые точны).

**Что это НЕ ново и что ново.** В тестовой копии файла Derand
уже есть конечный сертификат `D_closed`: `D_m = Q_m²` (нечётные)
и `D_m = 8P_m²` (чётные) для `m ≤ 20`, доказанный `decide`.
Новым здесь является только (а) перевод на язык `g'` (а именно
`g'` входит в фазы и в средние по единицам, а не `D_m` сам по
себе) и (б) претензия на все `m`, а не на `m ≤ 20`.
Наличие `D_closed` в текущем main не проверено (см. оговорку
в начале) — это первый пункт перепроверки.

**Маршрут структурного доказательства (набросок, не доказательство).**
`(3 + √8)^m = (1 + √2)^{2m}`, откуда `x_m = u_m² + 2v_m²`,
`y_m = u_m v_m` (с точностью до множителя 2 в нормировке `√8 = 2√2`,
проверить при формализации дословно). При нечётном `m` норма
`u_m² − 2v_m² = −1` даёт `x_m − 1 = 2u_m²`; при чётном `m` норма
`= +1` даёт `x_m − 1 = 4v_m²`. Остаётся лемма о НОД:
`gcd(2u_m², u_m v_m) = u_m` (нечётный случай) и
`gcd(4v_m², u_m v_m) = v_m` (чётный случай) — из взаимной простоты
`u_m, v_m`, следующей из нормы `±1`. Это элементарная арифметика
в `ℤ[√2]`, а не аналитика; именно поэтому кандидат считается
реально доказуемым, а не «ещё одной редукцией».

**Убийца.** Любое `m`, где `D_m ≠ (g'_m)²` (нечётное) или
`D_m ≠ (g'_m)²/2` (чётное); любое `m`, где `gcd(x_m − 1, y_m)`
не равен `u_m`/`v_m`. Один такой `m` убивает C1 полностью,
без «поправок». Также убийцей является ошибка в нормировке
`√8` против `√2` при переводе в Lean: если `y_m ≠ u_m v_m`
дословно, маршрут рушится, и это должно выясниться на этапе
выписывания определений, а не в середине доказательства.

### C2. Равномерность ν по окну с разбросом не более 1 — КАНДИДАТ (счётная лемма)

**Формулировка (счётная часть).** Пусть окно — как в §1
(`N ∈ (⌊X⌋, ⌊2X⌋]`, `gcd(N, D_m) = 1`), и `ν_N` — обратный
к `N` по модулю `g'_m` (то есть `ν_N · N = 1` в `ZMod g'`).
Тогда для любых двух единиц `ν, ν'` число появлений
`ν` и `ν'` в окне отличается не более чем на 1.

**Что проверено.** Подсчёт для `m = 3, 4, 5, 6` и всех целых
`X = 1..2000`: максимальный разброс по единицам равен 1
(в каждом случае; при малых `X` это тривиально, так как
разброс между 0 и 1 тоже равен 1 — нетривиальны большие `X`).
Примеры при больших `X`:

| m | X | всего N в окне | единиц | min | max |
|---|---|---|---|---|---|
| 3 | 20000 | 8572 | 6 | 1428 | 1429 |
| 4 | 20000 | 6666 | 16 | 416 | 417 |
| 5 | 20000 | 9756 | 40 | 243 | 244 |

**Почему это не чудо, а почти тривиальность — и почему это важно.**
`gcd(N, D_m) = 1` при `g' ∣ D_m` и одинаковых простых делителях
`D_m` и `g'` (для замороженного отображения это следует из C1:
`D_m` — квадрат или полуквадрат `g'`) эквивалентно тому, что
вычет `N mod g'` — единица. А число целых чисел в любом интервале
с заданным вычетом по модулю `g'` отличается по вычетам не более
чем на 1. Обратное отображение — биекция на единицах, поэтому
тот же разброс наследуется счётами `ν`. То есть «равномерность
по единицам» на уровне подсчёта не требует аналитической
эквидистрибуции вообще.

**Что остаётся открытым.** Из разброса `≤ 1` следует оценка
вида `|winAvg − nuAvgUnits| ≤ φ(g') · max_ν B(ν) / T`,
где `T` — число `N` в окне (доказательство: `c_ν ∈ {q, q+1}`,
`|c_ν − T/φ| < 1`, суммирование по `ν`). Но чтобы получить
оценку вида `D/X`, нужна явная нижняя граница `T ≥ c·X`
(плотность чисел, взаимно простых с `D_m`, минус краевые
эффекты блоков длины `D_m`). Эта нижняя граница — отдельный,
хотя и элементарный, шаг; без неё C2 — счётная лемма, а не
готовая `hEquidistUnits`. Также: для нецелых `X` окно в Lean
использует `⌊X⌋`, `⌊2X⌋` — числовой тест выше при целых `X`
этого различия не видит, и при формализации его надо проверить
отдельно. И наконец, константа: оценка через `φ(g')·max B`
не обязана совпадать с целевой константой моста (расхождение
порядка `2π` в границе 175 — отдельная открытая проблема,
которую C2 не закрывает и не маскирует).

**Убийца.** Окно, в котором разброс счётов по единицам `≥ 2`
при целых `X`; `m`, где простые делители `D_m` и `g'` различаются
(тогда `gcd(N, D) = 1` не эквивалентно единичности вычета);
`ν_N`, не являющийся обратным к `N` (тогда вся лемма неприменима
— это проверка гипотезы, а не контрпример к счёту).

### C3. Формула Рамануджана для среднего по единицам при конечном носителе `ĝ` — КАНДИДАТ

**Формулировка.** Пусть `ĝ` имеет конечный носитель (игрушечный
случай; общий `ĝ` — предельный переход, здесь не рассматривается).
Тогда

```
nuAvgUnits(Btup) = Σ_{n,n'} phiFun(n) · conj(phiFun(n'))
                   · c_{g'}(y'·(NmZ(n) − NmZ(n'))) / φ(g'),
```

где `c_q(a)` — сумма Рамануджана,
`c_q(a) = Σ_{ν ∈ (Z/q)ˣ} exp(2πi·ν·a/q)`,
и `c_q(a) = μ(q/d)·φ(q)/φ(q/d)` при `d = gcd(a, q)`.
В частности, слагаемые с `NmZ(n) = NmZ(n')` дают множитель 1
(«диагональ по Nm»), а остальные — целочисленные веса
`c_{g'}(·)/φ(g')`, которые могут быть отрицательными.

**Что проверено (float, не точное доказательство).**
Прямое вычисление `B(ν)` по определению и сравнение со
средним по единицам — против формулы Рамануджана:

| Случай | среднее по единицам | предсказание Рамануджана | разница |
|---|---|---|---|
| m=3, ĝ: 1, ½, ½ на {−1,0,1} | 6.562500000000 | 6.562500000000 | 5·10⁻¹⁴ |
| m=3, ĝ: 1, ¼, ¾ (асимм.) | 3.691406250000 | 3.691406250000 | 8·10⁻¹⁵ |
| m=4, ĝ: 1, ½, ½ | 28.062499999997 | 28.062500000000 | 3·10⁻¹² |
| m=2, ĝ: 1, ½, ½ | 5.000000000000 | 5.000000000000 | 3·10⁻¹⁵ |

Разложение на диагональ по Nm и внедиагональ показывает,
почему диагональное приближение здесь ложно:

| Случай | диагональ (Nm = Nm') | внедиагональ | итог |
|---|---|---|---|
| m=3, симм. | 12.875000 | −6.312500 | 6.562500 |
| m=4, симм. | 26.687500 | +1.375000 | 28.062500 |
| m=3, асимм. | 13.023438 | −9.332031 | 3.691406 |

Внедиагональный вклад сравним с диагональным и меняет знак —
любая «диагональная формула» для `nuAvgUnits` убивается первой
же строкой таблицы.

**Маршрут структурного доказательства (набросок).**
Это тождество характеров: среднее по единицам от
`exp(−2πi·ν·a/g')` есть ровно `c_{g'}(a)/φ(g')` по определению
суммы Рамануджана; подстановка в `|Σ_n|²` и перегруппировка
двойной суммы даёт формулу. Математически это стандартно;
открытым для проекта является только (а) точная сверка
нормировок фазы (`−ν·y'·Nm/g'` против `+ν·a/g'`, знак
неважен для `c_q`, так как `gcd(−a,q) = gcd(a,q)`, но в Lean
это надо выписать), (б) предельный переход от конечного
носителя к суммируемому `ĝ` (оценка хвоста через `s0, s2`
уже есть в мосте — это надо связать, а не переоткрывать),
(в) формализация суммы Рамануджана в Mathlib в нужной форме
(проверить наличие, а не предполагать).

**Убийца.** Игрушечный `ĝ`, где прямое среднее и формула
Рамануджана расходятся за пределами float-ошибки; носитель,
содержащий моду с `NmZ`, кратным `g'` (тогда вес равен 1,
и «внедиагональ» частично маскируется под диагональ —
тест обязан включать такие моды); `y'`, не взаимно простое
с `g'` в используемой нормировке (тогда `y'·a` пробегает
не все классы, и формула с `c_{g'}(y'·Δ)` всё равно верна,
но наивная замена `c_{g'}(Δ)` — ложна; это готовый
контрольный тест).

## 5. Следующие эксперименты по этому протоколу (в порядке приоритета)

1. **Следы.** Для малых `m, N` (взаимно простых с `D_m`)
   вычислить `k*` и проверить `N·k* ≡ −1 (mod e)` для всех
   `e ∣ D_m`. Пример `m = 3, D = 196`: `N = 3 → k = 65`,
   `N = 9 → k = 87`, `N = 19 → k = 165`; во всех случаях
   `N·k ≡ 195 ≡ −1 (mod 196)`, в частности `≡ 13 ≡ −1 (mod 14)`.
   Угадываемая структура: зависимость `k* mod e` только от
   `N mod e` — это уже доказанная фазовая лемма; эксперимент
   здесь служит контролем протокола, а не открытием.
2. **Форм-фактор как профиль.** Для конечного носителя `ĝ`
   построить таблицу `B(ν)` для всех `ν` (не только единиц)
   и угадать, при каких `ν` профиль вырождается
   (например, симметрия `B(ν) = B(−ν)` при вещественном `ĝ`,
   периодичность по делителям `g'`). Убийца: комплексный `ĝ`,
   ломающий симметрию.
3. **Окно и `T`.** Вычислить точную нижнюю границу `T(X)`
   для `m = 3..7` и угадать её замкнутую форму через
   `φ(D_m)/D_m` и краевой член (не более `D_m`).
   Это недостающий шаг C2.
4. **Предел по `ĝ`.** Для растущих носителей `ĝ`
   (например, гауссовых весов, обрезанных на `|k| ≤ K`)
   проверить, стабилизируется ли `nuAvgUnits` и с какой
   скоростью по `K` — это числовой аналог оценки хвоста
   через `s0, s2`. Убийца: медленная стабилизация, указывающая
   на неверную нормировку.
5. **PsiMode при `t*`.** Для игрушечного конечного набора
   мод `c, Q` проверить равенство `PsiMode(t*(N₁)) =
   PsiMode(t*(N₂))` при `N₁ ≡ ±N₂ (mod g')` численно —
   как контроль того, что фазовая лемма воспроизводится
   независимым кодом, а не только цитируется из Lean.

## 6. Что этот метод принципиально не даёт

- Численное совпадение не даёт микроскопической BGS:
  все величины здесь — конечные (`m`, `N`, `g'`) или
  средние по конечному окну. Предел `N → ∞` и переход
  от среднего по окну к спектральной статистике — отдельные
  аналитические шаги, которые эксперимент не заменяет.
- Эксперимент не различает «формула верна для всех `m`»
  и «формула верна для `m ≤ 30`»: именно поэтому holdout
  и структурный маршрут обязательны, а заголовок каждого
  кандидата содержит слово КАНДИДАТ.
- Эксперимент с игрушечным `ĝ` не говорит ничего о
  физическом `ĝ` (J0/гауссовом ансамбле) кроме структуры
  формул: значения `s0, s2`, положительность, симметрия `c`
  для настоящего ансамбля — отдельные открытые вопросы
  (см. пробелы 149/152).

## Приложение: воспроизводимые фрагменты кода

Фрагменты ниже — не часть доказательства; они фиксируют,
как именно получены числа в §4, чтобы любой мог их
пересчитать и убить.

```python
from math import gcd

def pell_table(M):
    x, y = 1, 0
    out = []
    for m in range(1, M + 1):
        x, y = 3*x + 8*y, x + 3*y
        d = gcd(x - 1, y)
        out.append((m, x, y, 2*(x-1), d, (x-1)//d, y//d))
    return out

def totient(n):
    r, t, p = n, n, 2
    while p * p <= t:
        if t % p == 0:
            while t % p == 0:
                t //= p
            r -= r // p
        p += 1 if p == 2 else 2
    if t > 1:
        r -= r // t
    return r

def mobius(n):
    if n == 1:
        return 1
    t, p, cnt = n, 2, 0
    while p * p <= t:
        if t % p == 0:
            cnt += 1
            t //= p
            if t % p == 0:
                return 0
        p += 1 if p == 2 else 2
    if t > 1:
        cnt += 1
    return (-1) ** cnt

def ramanujan(q, a):
    d = gcd(a, q)
    return mobius(q // d) * totient(q) // totient(q // d)

def window_unit_counts(X, Dm, gp):
    cnt = {}
    for N in range(X + 1, 2*X + 1):
        if gcd(N, Dm) != 1:
            continue
        nu = pow(N, -1, gp)
        cnt[nu] = cnt.get(nu, 0) + 1
    units = [u for u in range(gp) if gcd(u, gp) == 1]
    vals = [cnt.get(u, 0) for u in units]
    return min(vals), max(vals), sum(vals)
```

Проверка, которую обязан пройти каждый новый запуск:
`window_unit_counts` даёт `max − min ≤ 1` для `m = 3..6`,
`X ≤ 2000` (при целых `X`); `pell_table(30)` удовлетворяет
C1; сумма Рамануджана, посчитанная прямым суммированием
по единицам, совпадает с формулой через `μ, φ` для всех
`q ≤ 200`, `|a| ≤ 200` (этот тест в работе не запускался
в явном виде для всех `q, a` — при воспроизведении
запустить первым, до использования формулы).
