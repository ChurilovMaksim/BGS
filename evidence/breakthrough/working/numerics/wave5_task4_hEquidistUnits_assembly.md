## 1. Объекты и область действия

Для `m ≥ 1` (в сборке — только `m = 3, 4, 5, 6`):

- `D = D_m = 2·(pellX m − 1)`, `g' = gp m = (pellX m − 1)/gcd(pellX m − 1, pellY m)`.
- `R = rad(D)` — произведение различных простых делителей `D`;
  `ρ = φ(D)/D = φ(R)/R` — плотность единиц.
- Окно для **целого** `X`: `W_X = {X < N ≤ 2X, gcd(N, D) = 1}`.
  (В main окно определено через `⌊X⌋₊`, `⌊2X⌋₊` при вещественном `X`;
  для целого `X` определения совпадают. Вещественный случай — gap G7.)
- `ν_N = N⁻¹ mod g'` для `N ∈ W_X`; при `rad(D) = rad(g')` это единица mod `g'`.
- `Btup(ν) = |Z_all(η)[ν]|²`, `ν ∈ (ℤ/g')ˣ` — предельный профиль из `dlib`
  для настоящего кика при силе `η`.
- `nuAvgUnits = (1/φ(g'))·Σ_ν Btup(ν)`, `S = Σ_ν Btup(ν) = φ(g')·nuAvgUnits`.
- `winAvg(X) = (1/|W_X|)·Σ_{N∈W_X} Btup(ν_N)`,
  `diff(X) = winAvg(X) − nuAvgUnits`.
- `η` — только сетка проекта `{0.5, 1, 2, 5, 10, 25, 50, 100, 200}`.
  Вне сетки сборка ничего не утверждает.

Настоящий кик (из `model.py`): `c(0,±7) = 0.45`, `c(0,±1) = 0.05 ∓ 0.005i`,

## 2. Вывод: S-маршрут и пороги

Пусть `c_ν = #{N ∈ W_X : ν_N = ν}`, `dev_ν = c_ν − |W_X|/φ(g')`.
Тогда `Σ_ν dev_ν = 0` и

```
diff(X) = (1/|W_X|) · Σ_ν dev_ν · Btup(ν)
        = (1/|W_X|) · Σ_ν dev_ν · (Btup(ν) − nuAvgUnits).
```

Если разброс счётов ≤ 1 (кусок 2), то `|dev_ν| ≤ 1` для всех `ν`
(счёты — целые, отличающиеся не более чем на 1, а их среднее лежит
между минимумом и максимумом), и при `Btup ≥ 0` получается S-маршрут:

```
|diff(X)| ≤ S / |W_X|.                                            (1)
```

Блочный подсчёт mod `R` (кусок 2) даёт счётную границу

```
|W_X| ≥ φ(R)·(X/R − 1) = ρ·X − φ(R),      |W_X| ≥ ρ·X/2 при X ≥ 2R.  (2)
```

Отсюда три формы одной и той же оценки (при условии кусков 1–4):

- (A) Точная по счёту: `|diff(X)| ≤ S / (ρ·X − φ(R))` при `X > R`.
- (B) Чистая, с фактором 2: `|diff(X)| ≤ (2S/ρ) / X` при `X ≥ 2R`.
- (C) Форма моста (ветвь Deff): `|diff(X)| ≤ D·Deff / X` при `X ≥ X₀`,
  где `X₀ = D·Deff·φ(R) / (Deff·φ(D) − S)`,
  при условии `S < Deff·φ(D)`.

Проверка (C): достаточно `S·X ≤ D·Deff·(ρX − φ(R))`;
так как `D·ρ = φ(D)`, это равносильно
`D·Deff·φ(R) ≤ (Deff·φ(D) − S)·X`, т.е. `X ≥ X₀`.
Форма (B) следует из (A) при `X ≥ 2R`, так как тогда `ρX − φ(R) ≥ ρX/2`
(здесь использовано `φ(R) = ρ·R ≤ ρX/2`).
Форма (C) — следствие (A), а не независимая оценка; её константа
`D·Deff` заведомо грубее, чем `2S/ρ`, как только `S` много меньше
порога (см. таблицу §3).

Замечание о порогах: во всех четырёх случаях `X₀` лишь чуть больше `R`
(так как `S ≪ Deff·φ(D)`), т.е. точная ветвь Deff включается уже при
`X ≈ R`, а не при `X ≥ 2R`. Для целого `X` достаточно `X ≥ ⌈X₀⌉`.

## 5. Отношение к форме моста `D·min(s0^{2m}, Deff)/X`

В `nAverageTup_units` ветвь заявлена в виде
`|winAvg − nuAvgUnits| ≤ D·min(s0^{2m}, Deff)/X`.
Сборка §3 даёт ветвь Deff (`D·Deff/X`), но это НЕ то же самое, что
форма с `min`, и различия надо фиксировать точно:

- Если `Deff ≤ s0^{2m}`, то `min = Deff`, и форма (C) — это в точности
  форма моста. Если же `s0^{2m} < Deff`, то форма (C) слабее формы
  моста, и для неё нужна ещё ветвь `s0`.
- Ветвь `s0` в форме M03 C-sharp (`(4g'/X)·s0^{2m}`) следует из того же
  S-маршрута при тривиальной оценке `S ≤ φ(g')·s0^{2m}`,
  где `s0` — сумма модулей коэффициентов Фурье самого кика `exp(iηf)`
  (обозначим `s0_exp(η)`), а НЕ сумма модулей коэффициентов `f`
  (`s0_f = 1.110998`). Путаница здесь фатальна: оценка
  `Btup ≤ s0_f^{2m}` ЛОЖНА для настоящего профиля
  (`S/(φ(g')·s0_f^{2m})` достигает 3.97, 4.54, 6.21, 4.31 при
  `m = 3, 4, 5, 6`), а с корректным `s0_exp(η)` оценка тривиально верна,
  но пуста: `4g'·s0_exp^{2m}` лежит в диапазоне от `8.1·10²` (m=3, η=0.5)
  до `1.3·10²³` (m=6, η=200) — в `10⁵–10²⁰` раз выше наблюдаемого sup.
- Комбинированная оценка `|diff| ≤ min(D·Deff, 4g'·s0_exp^{2m})/X`
  (при порогах каждой ветви) влечёт форму моста, так как `4g' < D`
  при `m = 3..6` (56 < 196, 192 < 1152, 328 < 6724, 1120 < 39200).
  Но порог и константа C-sharp здесь НЕ перепроверены заново
  (в источниках фигурируют и `X ≥ 4g'`, и `X ≥ 4R/3` в разных
  выводах); поэтому комбинированная форма моста в сборке заявлена
  как СЛЕДСТВИЕ, ТРЕБУЮЩЕЕ ПЕРЕПРОВЕРКИ, а не как закрытый пункт.
  Закрытым (условно, по H1–H4) является только ветвь Deff §3.

## 6. Точная константа: предела нет, есть супремум по паттернам

Наблюдение волны 4, задачи 3 (численно, не доказано):
`X·|diff|` НЕ стабилизируется к пределу. От `X = 10⁴` до `10⁵`
это ограниченное колебание, циклически проходящее небольшой
репертуар значений (например, m=3, η=10: `{0, 2.4, 3.2, 7.8, 11.1,
17.4, 19.7}`; m=6, η=200: `{0, 61.2, 88.3, 134.0, 146.1, 149.4,
280.1}`), при `max|dev| ≤ 0.98` на всей сетке.
Механизм: `X·|diff| = (X/|W|)·|Σ_ν dev_ν(X)·Btup(ν)|`,
где `dev_ν(X)` определяется `X` по модулю малых модулей,
а `X/|W| → 1/ρ`. Честная точная константа поэтому такова:

```
C(m, η) = sup_X (X/|W_X|) · |Σ_ν dev_ν(X)·(Btup(ν) − nuAvgUnits)|,
```

супремум по вычетным паттернам, зависящий от `(m, η)` и не равный
ни `2π`, ни `D·Deff`, ни `4g'·s0^{2m}` (см. таблицу §4).
Разрешение старого расхождения «≈ 2π»: фактор `≈ 2π` в мосте
(заголовок, §4) — это отношение точечной константы первой ошибки
`(2·s0^m+1)·π·m·s2·s0^{m−1}` к `m·s2·s0^{2m−1}` из 175,
т.е. он принадлежит точечной ошибке, а НЕ оконной ошибке
`X·|winAvg − nuAvgUnits|`. Для оконной ошибки `2π` — ложный
кандидат: наблюдаемые значения составляют `0.2×–53×` от `2π`
в зависимости от `(m, η, X)`.

## 7. Что именно остаётся (gaps, по порядку)

**G1. Элаборация черновика радикала.** Черновик волны 4, задачи 2
(420 строк) — текст с `sorry`. Трудные места в Lean, а не в математике:
мост Int→Nat для `gp` (вычитание в `ℤ`, `toNat`, `Nat.gcd`/деление,
а все леммы о факторизации — в `ℕ`); API факторизации
(`Nat.factorization_mul/pow/gcd/div`, side conditions о ненулевых
значениях); переход «`A ≡ 2 (mod 4)` ⇒ `factorization A 2 = 1`»
(нужна вспомогательная лемма о числах вида `2 × odd`).
Математика наброска: норма `x² − 8y² = 1`, чётность/mod 4,
для нечётных `p`: `p ∤ x+1`, откуда `2·v_p(y) = v_p(x−1)`;
для `p = 2`: `v2(gp) = 1` при нечётных `m`,
`v2(gp) = 2 + v2(y) ≥ 2` при чётных `m`. Численно сверено для
`m = 1..30`. Закрытие G1 снимает H1.

**G2. Элаборация черновика единиц.** Черновик волны 3, задачи 4
(398 строк, 13 именованных теорем, все доказательства `sorry`).
По-настоящему трудно: сюръективность редукции единиц
`(ℤ/D)ˣ → (ℤ/g')ˣ` (L2) — нужен подъём единицы mod `g'` до единицы
mod `D`, т.е. prime avoidance / CRT по простым делителям `D`;
теория групп сама по себе этого не даёт; первый шаг — поиск
готовой леммы в Mathlib, черновик её существования НЕ предполагает.
Трудоёмко, но стандартно: подсчёт по полным блокам (L5–L6),
разбиение окна по единицам (L7, здесь используется H1),
книгkeeping с `ZMod.val`/обратными, нижняя граница `|W|` (L8).
Закрытие G2 снимает H2 и формализует сам S-маршрут (1).

**G3. Доказанная верхняя граница для `S` настоящего кика — связующее
место.** Это НЕ формализация вычисления, а аналитическая задача.
Численные `S` (§3) нельзя внести в Lean как «вычисленные»:
нужна доказанная оценка `S ≤ S_bound` с запасом, укладывающимся
в порог. Благодаря запасам пороги таковы (половина порога):
`S ≤ 2058` (m=3), `≤ 13824` (m=4), `≤ 2756840` (m=5),
`≤ 32928000` (m=6). Связующий случай — m=3 (всего 46× запаса).
Тривиальная оценка через `s0` здесь НЕ проходит:
с `s0_f` она ложна, с `s0_exp(η)` — пуста (до `10²³`).
Нужна либо новая аналитическая оценка, использующая нормировку
`|exp(iηf)| = 1` и структуру орбит (а не только `Σ|φ|`),
либо строгая интервальная арифметика для `Z(ν)` при каждом
`(m, η)` сетки, формализованная или хотя бы с полным протоколом
погрешностей. Пока G3 не закрыт, утверждение §3 остаётся условным
даже при закрытых G1–G2: H3 — это не «число посчитано», а
«число доказано меньшим порога».

**G4. Отождествление профилей и кика.** Нужно доказать (или точно
сформулировать как гипотезу с именем):
(a) `Btup` моста (через `kickMatInf`/кортежи) равен `|Z_all(η)|²`
из `dlib` для настоящего кика;
(б) параметр `η` в `dlib` соответствует коэффициентам Фурье
`exp(iηf)` в мосте (а не коэффициентам самой `f`);
(в) отождествление `kickMatInf` с настоящим квантовым киком
`exp(iτN·A_N)` — в main оно входит только как гипотеза `hTrU`
моста. Без (a)–(в) оценка §3 — это оценка для профиля `dlib`,
а не для объекта моста, и переносить её в `nAverageTup_units`
нельзя. Закрытие G4 снимает H4.

**G5. Точная константа как теорема.** Нужно:
(a) доказать, что `dev_ν(X)` зависит только от конечного набора
вычетных паттернов (периодичность по модулю малых модулей,
с учётом floors);
(б) вычислить `C(m, η)` из §6 точно (конечная проверка по паттернам)
для каждого `(m, η)` сетки;
(в) решить, какую формулировку несёт `hEquidistUnits`:
острую `|diff| ≤ C(m,η)/X` или грубую ветвь Deff §3.
Без (a) наблюдаемый sup из §4 — только численное наблюдение
на сетке `X ≤ 10⁵`, а не константа.

**G6. Общий `m`, `η` вне сетки, `m = 1, 2`.** Всё в §3 — конечные
экземпляры `m = 3..6`, `η` из сетки. Для общего `m` нет ни
равномерной оценки `S`, ни вычисления; рост `S(m, η)` с `m`
не изучен. Черновики G1–G2 сформулированы для общего `m`
(переменная `m`, условие `m ≥ 1`), так что общий случай упирается
именно в равномерную оценку `S` (G3 для всех `m`) и в G4.
Случаи `m = 1, 2` в сборку не входят: `m = 1` — отдельная история
(старая форма `hEquidist` там доказательно ложна, новая —
через единицы — требует отдельной проверки), `m = 2` численно
в волнах 3–4 не считался.

**G7. Вещественный `X`, floors, краевые случаи.** Main определяет
окно через `⌊X⌋₊`/`⌊2X⌋₊` при вещественном `X`; сборка — для
целого `X`. Перенос требует учёта floors в счётах и в (2)
(поправка порядка `φ(R)` уже заложена в (2), но формальный перенос
не проделан). Пустое окно: при `X ≥ ⌈X₀⌉ > R` граница (2)
положительна, так что окно непусто; при меньших `X` оценка (1)
требует отдельного условия `W_X ≠ ∅` (как в черновике).

**G8. Стыковка с `nAverageTup_units` в main.** Даже при закрытых
G1–G7 нужно проверить совпадение формулировок дословно:
определение окна в main, определение `winAvg`/`nuAvgUnits`,
что именно называется `Btup` в мосте, и какая константа
(`D·Deff`, `D·min(...)`, или `2S/ρ`) вставляется в утверждение.
Несовпадение в одном определении обнуляет перенос.
Также обязательна перепроверка всех SHAs с HEAD, актуальным
на момент переноса (см. оговорку в начале).

## 8. Что НЕ последует, даже если G1–G8 закрыть

1. **НЕ ветвь Deff для общего `ĝ`.** Контрпримеры волны 2 стоят:
   m=4, uniform на 9 точках — асимптотический провал ветви
   с фактором ≈ 1.92; m=6, uniform на 10 точках — до 3.50;
   alternating K=8 — провал при m=4 (1.017) и m=6 (1.105).
   Сборка специфична для настоящего кика именно потому, что
   вход `S` — специфичен для него. Любое утверждение «ветвь Deff
   верна» без квалификатора «для настоящего кика» будет ложным
   в общем виде.
2. **НЕ ветвь `s0` в наивной форме.** С `s0_f` она ложна (§5);
   с `s0_exp` — верна, но пуста. Закрытие G1–G8 не делает
   `s0_f`-версию верной и не делает `s0_exp`-версию острой.
3. **НЕ точная константа.** G1–G4 дают верхнюю оценку
   (S-маршрут), а не значение `C(m, η)` из §6. Точная константа —
   отдельный результат (G5), и S-маршрут её принципиально
   не даёт (потеря 6.7×–30× даже в форме (B), 308×–685780×
   в форме (C) относительно наблюдаемого sup).
4. **НЕ BGS-001, НЕ TRACE-005, НЕ спектральная универсальность.**
   hEquidistUnits — один оконный шаг в цепочке TRACE-175.
   Вне сборки остаются: hSep в общем виде (O* при m=12 убито
   явным контрпримером волны 4; O' при m=12 — носитель
   контрпримера не проверен), отождествление `kickMatInf`
   (частично G4, но в полном объёме — отдельно), J0-ансамбль,
   аналитический слой 149 (`hTrace`, `hAvg`, `hE`, `hPair`,
   симметрия `c`, положительность), предельный оператор,
   контроль до времени Гейзенберга. Оконная лемма — не спектр.
5. **НЕ COE/CUE и НЕ форм-фактор.** Среднее по окну — не спектр;
   вердикты M02/M04/M05 (нет `λ₁` в main, резонансное предсказание
   не работает на модели, DBM-часы — только для зашумлённой
   системы) сборкой не затрагиваются.
6. **НЕ общий `m` и НЕ все `η`.** Закрытие G1–G8 для `m = 3..6`
   и сетки `η` даёт конечные экземпляры. Перенос на все `m`
   и все `η` требует равномерной оценки `S` (G6), которой нет.
7. **НЕ исправление реестра.** Ничего из сборки не меняет
   `state`/`ledger_status` записей TRACE-175 или других:
   условное утверждение с гипотезами H1–H4 — не основание
   для пометки «proved», пока H3 не заменена доказанной
   оценкой (G3) и H1/H2/H4 — формализованными леммами.
